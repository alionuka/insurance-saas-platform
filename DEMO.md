## 🎙 Talking points for Q&A

**"What is the ML doing here?"**
> Three models: a gradient boosting classifier for risk scoring, a logistic regression with TF-IDF text features for fraud detection, and content-based recommendations using cosine similarity. Each model was selected via 5-fold cross-validated GridSearch comparing multiple algorithms. SHAP feature contributions are computed at inference time and persisted alongside each prediction — agents and customers see not just a score, but *why*.

**"Where does the data come from?"**
> Synthetic dataset generated by `ml-service/training/generate_*.py` — 10 000 samples with realistic distributions (log-normal income, Poisson claim counts, normal credit scores) and a probabilistic ground-truth model with documented non-linear interactions. This let me isolate methodological contributions from data-quality issues that typically dominate public datasets. The generator script is reproducible (seed=42) and fully documented.

**"How is this multi-tenant?"**
> Four roles with different scoping. Company admins see only their company's products, policies, and claims — filtered at the service layer by `product.companyId`. Platform admins see everything. Customers and agents have their own access patterns. The audit log captures every privileged action for compliance.

**"What about security?"**
> Short-lived 15-minute access tokens with rotating one-time-use refresh tokens (hashed in DB with bcrypt). Rate-limited login, validated input via class-validator, CORS allow-list, Stripe webhook signature verification, full audit trail. Every endpoint that mutates data requires both authentication and role authorization.

**"How is this production-grade?"**
> Sentry error tracking on both client and server, structured pino logs with per-request UUIDs, split `/health/live` and `/health/ready` probes with DB and ML service checks, Docker containerized, deployed on Vercel + Railway with auto-deploy on every git push, 72 e2e tests gated by GitHub Actions CI, OpenAPI documentation at `/api/docs`, JSON migrations versioned in source control.

**"What technologies?"**
> Frontend: Next.js 16 (App Router, Server Components), TailwindCSS, Recharts, Sonner, Framer Motion. Backend: NestJS 11, Prisma 5, PostgreSQL 15, Stripe SDK, Resend for email. ML: FastAPI, scikit-learn, SHAP, pandas, numpy. Auth: JWT HS256 + bcrypt + Passport.js. Observability: Sentry + nestjs-pino.

**"Why does Stripe show Test Mode in the demo?"**
> Deliberate choice for a thesis demonstration. Stripe Test Mode allows the full integration to be shown end-to-end — webhook signatures verified, Checkout sessions created, success/cancel flows, refund handling — without involving real money or requiring full KYC business verification. Switching to Live Mode for a production deployment is a single environment-variable swap (`STRIPE_SECRET_KEY`, `STRIPE_PUBLISHABLE_KEY`, `STRIPE_WEBHOOK_SECRET` all rotate). Test Mode also enables demonstrating edge cases that production would make impossible: declined cards (`4000 0000 0000 9995`), 3-D Secure challenge (`4000 0025 0000 3155`), insufficient funds. The code path is identical — only the keys differ.

**"How is this production-grade if you're running Test Mode?"**
> Two separate concerns. The *infrastructure* is production-grade: Vercel CDN, Railway managed Postgres, Cloudflare R2 storage, Sentry monitoring caught a real Prisma transaction timeout in production, Lighthouse scores 100/94/100/100. The *payment provider mode* is Test for safety reasons described above — switching to Live is a configuration change, not an architectural one. The webhook signature verification, idempotency handling, and audit log entries are the same in both modes.

## 🛡 Common pitfalls during live demo

| Problem | Fix |
|---|---|
| Quick-login button does nothing | Cookies blocked — disable strict tracking prevention in browser |
| Recommendations show "Failed to load" | ML service cold-start (~30 sec wake-up) — refresh in 30 sec |
| Some pages slow on first hit | Vercel cold-start — open all pages once before demo |
| Stripe checkout shows red "TEST MODE" banner | This is intentional — we run Stripe in Test Mode for the demo (see Q&A "Why Test Mode?" below). Use card `4242 4242 4242 4242`, any future expiry, any CVC. |
